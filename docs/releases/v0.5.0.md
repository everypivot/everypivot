# EveryPivot v0.5.0 Release Notes

Release date: 2026-09-10

v0.5.0 introduces `pivot-pattern` schema v1.5 to separate investigative evidence
from conditional assessment hints. It changes the metadata contract consumed
by registries and downstream tools. Consumers must update their handling of
assessment fields before adopting this distribution.

## Changed

- Every pattern declares `assessment_mode`: `evidence_only` or
  `candidate_assessment`. Evidence-only records omit `assessment`; conditional
  candidates include a complete hint and `assessment_requirements`.
- All 176 patterns have reviewed defaults: 175 are evidence-only, and
  `ADTECH_AD_REQUEST_TO_INFECTION_HIT` retains a conditional observation-to-incident
  hint with five qualifying-evidence requirements. Its match alone does not
  establish infection, actor attribution or an accepted assessment.
- Pattern versions advance to 2.0.0 for the 168 previously stable records and
  0.2.0 for the eight pre-1.0 records. Selectors, hops, hazards, provenance,
  suppression controls and lifecycle lanes are preserved.
- Native validation and registry generation check a pinned SAIL v0.4 DRAFT
  predicate/role/object/scope contract. Missing or corrupt contract data blocks
  generation. Incomplete and incompatible active hints cannot be exported.
- Registry entries carry explicit compatibility coverage; candidates retain
  qualifying requirements. The browser distinguishes evidence-only results,
  conditional candidates and unchecked mappings.
- Offline pattern archives and release packs carry the schema and pinned
  contracts with their original attribution. Release packs include the bridge
  checker and validate their copied corpus before generating artifacts.
- CI checks complete bridge compatibility and confirms preview bundles carry
  the preview channel in both the registry index and release manifest.

## Migration

Do not assume an `assessment` block exists. For evidence-only patterns, preserve
the finding and its hazards without inventing a default claim. For candidates,
preserve the complete hint, compatibility record and qualifying requirements;
runtime evidence, contradictions, confidence and acceptance remain separate.
Unknown or unchecked states must not enable assessment generation.

See [schema migration](../SCHEMA_MIGRATION.md) and
[evidence and assessment hints](../ASSESSMENT_BRIDGE.md). The older proposal for
families, facets and case-bound objects is future design work, outside this
version's scope. Historical releases and deliberate legacy fixtures retain
their original schema versions.

## Boundaries

Counts remain 21 validated, 76 working_set and 79 deferred: 176 total. Schema
migration does not promote or demote a pattern. Formal compatibility does not
establish that an analytical conclusion is true. SAIL remains v0.4 DRAFT and its
model semantics are unchanged. Repository checks and transport fixtures do not
demonstrate compatibility with an independently deployed consumer.

This document describes the distribution contents. Publication and deployment
status must be established from the corresponding release and deployment
records; the presence of this file alone does not establish either.
