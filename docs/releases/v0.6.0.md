# EveryPivot v0.6.0 Release Notes

Release date: 2026-10-02

v0.6.0 adds explicit executable interpretations for focused pattern families.
Consumers must support authoring schema 1.6 and verify the referenced contract
bytes before executing those definitions. Legacy temporal-order strings remain
non-executable through this interface.

## Contracts and identities

- Forty-five definitions carry digest-bound finite execution contracts: 41
  migrated original patterns and four new companions. The other 134 original
  patterns remain outside this executable migration.
- Event times, extraction, collection availability and historical knowledge
  have distinct bindings. Reprocessing does not manufacture a new sighting or
  backdate analyst knowledge.
- Whole certificates, SPKI/public keys, issuer/serial selectors, signature
  material and whole-file hashes have separate identity rules. JA3 client
  observations and JA3S server observations use separate patterns.
- Named bindings define intermediate nodes, joins and emitted identities.
  Constructed observations remain evidence. Reported ownership does not
  establish control; sanctions traversals do not determine legal exposure.
- Source revisions, preserved bytes and hashes, conflicting assertions,
  analyst-selected periods and bounded search remain visible.

## Migration

New companions are `OSINT_TLS_JA3S_TO_FQDNS`, `CTI_IP_TO_LISTING_ASSERTIONS`,
`CTI_ASN_TO_EXPLICIT_LISTING_ASSERTIONS` and `CTI_ASN_TO_LISTED_INFRASTRUCTURE`.
The broad `CTI_SBL_HOSTING_RISK` definition remains available as deprecated,
non-executable compatibility metadata. Callers must choose a scoped successor.

Authoring schema 1.5 remains distributable without an execution reference.
Consumers that cannot verify or interpret a 1.6 execution reference must report
unsupported rather than interpret its documentary hop or temporal strings.
Individual pattern versions, registry release, authoring schema, semantic
contracts and adapter profiles have separate version identities.

See [schema migration](../SCHEMA_MIGRATION.md),
[semantic execution](../SEMANTIC_EXECUTION_CONTRACT.md) and
[adapter profiles](../ADAPTER_QUERY_PROFILES.md).

## Validation and distribution

Validation rejects duplicate pattern IDs, future observations outside the
selected date window, inconsistent bounded one-hop evidence and incompatible
assessment hints. Mathematical integer handling agrees with JSON Schema;
UTF-8 and STIX mapping checks preserve their declared input boundaries.
Pattern archives and standalone packs include referenced semantic contracts,
dependencies and synthetic regression cases. Browser compatibility is bound
to the exact hint, requirements and pinned assessment manifest.

The hybrid Neo4j semantic profile admits two exact JA3/JA3S contracts for
normalized graph persistence/readback followed by portable Ruby evaluation.
It does not implement the grammar in Cypher or parse raw network evidence.
The original three-target one-hop pilot and bounded OpenCTI/STIX mapping retain
their own scope; no deployed OpenCTI consumer acceptance is claimed.

## Boundaries

Counts are 21 validated, 77 working_set and 82 deferred: 180 total. There are
179 evidence-only definitions and one conditional candidate hint. Existing
patterns retain their lifecycle lanes and review dates. Synthetic tests do not
supply source independence, confidence, attribution or accepted assessments.
The independently versioned semantic contracts remain drafts; SAIL remains
v0.4 DRAFT with its existing pin and licensing.

This document describes distribution contents. Publication and deployment
status are established by release and deployment records.
